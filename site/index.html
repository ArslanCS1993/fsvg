FSVG

A flowchart language that compiles to x86-64 machine code. There are no letters in a program — every instruction is drawn.

11instructions
15registers
26glyphs, all unique
847lines of compiler

An instruction is written as an emoji and drawn as an SVG icon. Both are required and they must agree: the emoji is the key the compiler resolves — an exact codepoint, never a guess from how the picture looks — and the drawing is what a human reads. Because resolution is exact, a hand-edited icon cannot silently compile to the wrong opcode; it just stops being the instruction you drew.

Registers are identified by outline, not colour — eight distinct shapes in two hue families give sixteen registers. Colour alone would fail for a colour-blind reader and would vanish on a monochrome printer.

A sine wave 01-hello

Indexes a 32-byte table, multiplies, and writes a real SVG document. This is the first program that produces something you can look at.

the program (77 lines, no letters)
<!-- FSVG program 1 - the first thing that boots.

     It walks a sine table with an index, scales the result into screen
     coordinates, and writes a real SVG document to stdout.

        ./01-hello > out.svg

     Every number in this program is either a SIZE or a MEMORY ADDRESS. Every
     other value is a register or a named constant - there is not one magic
     number in the body. The sine table is 32 bytes read by index, which is
     what makes it a table and not a literal. -->

     data-const="POINTS=160,SCALE=5,MID=240,TABLE_MASK=31,ZERO=0,ONE=1,STATUS=0"
     data-bytes="SINE=0,18,34,50,64,75,83,88,90,88,83,75,

  <g>
    <rect id="start" x="40" y="30" width="230" height="38"
          data-entry="1" data-next="init_i">PRINT HEAD</rect>

    <!-- i = 0 -->

          data-next="loop">MOV RCX, ZERO</rect>

             data-lt="body" data-eq="done" data-gt="done">CMP RCX, POINTS</polygon>

    <!-- idx = i &amp; 31  ->  wraps the sine table without a division -->
    <rect id="body" x="360" y="204" width="240" height="38"

          data-next="mul">MOV RAX, RCX</rect>
    <rect id="mul" x="360" y="452" width="240" height="38"
          data-next="add_x">MUL RAX, SCALE</rect>
    <rect id="add_x" x="360" y="514" width="240" height="38"

    <rect id="y_mid" x="360" y="576" width="240" height="38"
          data-next="y_sub">MOV RBX, MID</rect>
    <rect id="y_sub" x="360" y="638" width="240" height="38"
          data-next="put_le">SUB RBX, RDX</rect>

    <!-- One path segment per point:  L x , y
         Emitting "L" before each point is what removes the need for a
         separator BETWEEN points. Printing the comma between x and y alone
         produced "5,240" + "10,214" = "5,24010,214", and a separator after y
         alone produced "5240" - the SVG path is only unambiguous if each
         point carries its own command letter. -->
    <rect id="put_le" x="700" y="452" width="200" height="38"
          data-next="put_x">PRINT LE</rect>
    <rect id="put_x" x="700" y="514" width="200" height="38"
          data-next="put_comma">PUTINT RAX</rect>
    <rect id="put_comma" x="700" y="576" width="200" height="38"

    <rect id="put_y" x="700" y="638" width="200" height="38"
          data-next="inc">PUTINT RBX</rect>

    <!-- i = i + 1, and the edge that closes the loop -->
    <rect id="inc" x="360" y="700" width="240" height="38"
          data-next="loop">ADD RCX, ONE</rect>

    <rect id="done" x="40" y="330" width="230" height="38"
          data-next="bye">PRINT TAIL</rect>
    <rect id="bye" x="40" y="392" width="230" height="38"
          data-next="bye">EXIT STATUS</rect>
  </g>
</svg>

Kernel entry: entry_SYSCALL_64 03-entry-syscall

The first instructions a Linux kernel runs on a syscall. Real swapgs, real push, real sysret. Compiles and matches the kernel instruction trace -- but cannot run as a userspace program, because swapgs is privileged and faults immediately in ring 3.
